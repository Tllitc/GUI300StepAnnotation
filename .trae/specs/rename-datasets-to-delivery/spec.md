# 数据集交付重命名工具 Spec

## Why

交付长步骤采集数据时，源数据按 `平台/采集人员/文件夹编号` 分散存放，各人员、各平台内部编号重复，无法直接作为一个整体交付数据集。需要在 `datasubtool` 下提供一个 Qt + Python 桌面工具，按交付清单（Excel）把源数据集统一复制、重命名并输出为标准结构，同时生成源目录与输出目录的映射表，便于核对与追溯。

## What Changes

- 新增 `datasubtool/` 工具，包含核心逻辑模块与 PyQt5 界面。
- 界面支持选择交付 Excel、数据母目录、目标目录，点击「开始转换」执行。
- 读取 Excel 的 `平台`、`采集人员`、`文件夹编号` 列，在母目录中定位 `母目录/平台/采集人员/文件夹编号`。
- 平台名做归一化匹配（如 `安卓`/`Android`、`ios`/`IOS`/`iOS`、`Mac`/`macos`、`windows`/`Windows`），并与母目录下真实平台目录名对齐。
- 同一平台内按 Excel 行序排序，从用户为该平台填写的起始序号开始编号（默认 `gui_000001`，便于多批次续号）。
- 输出结构为 `目标目录/平台/gui_XXXXXX/`，各平台独立编号。
- 数据集内 `<编号>.json` 与 `<编号>_<数字>.png` 的文件名前缀统一改为新编号；JSON 中引用截图名的字段值同步改写，图片、JSON、JSON 内引用三者保持一致。
- 复制时只保留数据集白名单文件（`<编号>.json`、`<编号>_<数字>.png`），`<编号>_coords.json`、`*_draft.json`、`*.bak`、`*.bak_<时间戳>` 等非数据集文件不复制。
- 采用**复制**方式，不修改源目录。
- 转换前做预检：Excel 列缺失、源目录不存在、Excel 重复行、目标编号目录已存在时**中止且不做任何复制**，在界面列出问题清单。
- 转换完成后在目标目录输出映射 Excel，记录每条数据集的源目录、原编号、新编号、输出目录与状态。
- 转换在工作线程中执行，界面显示进度与日志，支持取消（当前数据集完成后停止并输出已完成部分的映射表）。

## Impact

- 受影响能力：交付数据整理流程（新增独立工具，不影响现有采标/标注功能）。
- 受影响代码：新增 `datasubtool/core.py`、`datasubtool/app.py`、`datasubtool/tests/test_core.py`；不改动根目录现有模块。

## ADDED Requirements

### Requirement: 交付清单读取与平台归一化

系统 SHALL 从用户选择的 Excel 第一个工作表读取表头，按列名 `平台`、`采集人员`、`文件夹编号` 解析交付条目，并将平台列映射到数据母目录下真实存在的平台目录名。

#### Scenario: 平台别名匹配成功
- **WHEN** Excel 平台单元格为 `安卓`、`ios`、`IOS`、`Mac`、`windows`
- **THEN** 分别解析为母目录下真实目录 `Android`、`iOS`、`macos`、`Windows`（大小写不敏感，先精确匹配再按别名表匹配）

#### Scenario: 平台无法识别
- **WHEN** Excel 中某行平台值无法映射到母目录下的任何平台目录
- **THEN** 该行记为预检错误，列出 Excel 行号与平台值，转换中止

#### Scenario: 必需列缺失
- **WHEN** Excel 表头缺少 `平台`、`采集人员`、`文件夹编号` 中任一列
- **THEN** 界面提示缺失列名并中止，不做任何文件操作

### Requirement: 转换规划与冲突预检

系统 SHALL 在复制前生成完整转换计划：按平台分组、组内保持 Excel 行序，为每条数据集分配 `gui_%06d` 形式的新编号（各平台自用户填写的起始序号开始，默认 `gui_000001`），并校验源目录存在性、Excel 重复条目与目标路径占用情况。

#### Scenario: 规划成功
- **WHEN** 所有条目源目录均存在、无重复条目、目标目录下无同名平台/编号目录
- **THEN** 生成按平台分组的编号方案，进入复制阶段

#### Scenario: 目标编号已存在
- **WHEN** 目标目录中已存在计划写入的 `平台/gui_XXXXXX` 目录
- **THEN** 视为冲突，转换中止，界面列出所有冲突路径

#### Scenario: Excel 重复条目
- **WHEN** 两条记录解析出的源目录相同
- **THEN** 预检报告重复条目并中止，不重复复制

#### Scenario: 源目录缺失
- **WHEN** 某条记录对应的 `母目录/平台/采集人员/文件夹编号` 不存在
- **THEN** 预检报告缺失源目录，转换中止且不复制任何数据

### Requirement: 平台起始序号

系统 SHALL 允许用户为 Excel 中命中的每个平台分别填写本次导出的起始序号，使多批次输出的编号连续；未填写的平台默认从 1 开始。

#### Scenario: 默认起始序号
- **WHEN** 用户未修改命中平台的起始序号
- **THEN** 该平台数据集从 `gui_000001` 开始按 Excel 行序编号

#### Scenario: 多批次续号
- **WHEN** Windows 平台填写起始序号 6，且本次有 2 条 Windows 数据集
- **THEN** 分别输出为 `gui_000006`、`gui_000007`，其它平台仍按其自身起始序号编号

#### Scenario: 起始序号非法
- **WHEN** 起始序号为空、非整数或小于 1
- **THEN** 预检报告「起始序号无效」，整体中止且不复制任何数据

#### Scenario: 起始序号导致冲突
- **WHEN** 按起始序号计算出的目标目录已存在
- **THEN** 沿用编号冲突规则，预检中止并列出冲突路径

### Requirement: 数据集文件白名单过滤

系统 SHALL 将源数据集目录整体复制到 `目标目录/平台/新编号/`，仅复制数据集白名单文件并把文件名前缀改为新编号，其余缓存、备份等非数据集文件跳过不复制。

#### Scenario: 文件重命名
- **WHEN** 源目录包含 `gui_000003.json`、`gui_000003_0001.png` … `gui_000003_0123.png`，新编号为 `gui_000002`
- **THEN** 输出目录包含 `gui_000002.json`、`gui_000002_0001.png` … `gui_000002_0123.png`，白名单文件数量与内容（图片字节）一致

#### Scenario: 非数据集文件过滤
- **WHEN** 数据集目录内存在 `gui_000003_coords.json`、`gui_000003_draft.json`、`gui_000003.json.bak`、`gui_000003_coords.json.bak_20261028_145211`、`note.txt` 等非数据集文件（含隐藏目录内文件）
- **THEN** 这些文件不复制到输出目录，日志记录每个数据集跳过的文件数量与示例文件名

#### Scenario: 没有可复制的数据集文件
- **WHEN** 数据集目录内不存在任何白名单文件
- **THEN** 该数据集标记为失败并清理空输出目录，映射表备注记录「未找到可复制的数据集文件」

### Requirement: JSON 内部引用同步改写

系统 SHALL 改写数据集内 JSON 文件文本中所有以「原编号 + `_` 或 `.`」形式出现的旧编号引用（主要是 `observation.screenshot` 的图片文件名），使其指向重命名后的文件，且不改变 JSON 其余内容与排版。

#### Scenario: 截图引用改写
- **WHEN** JSON 中 `"screenshot": "gui_000003_0042.png"`，新编号为 `gui_000002`
- **THEN** 输出 JSON 中该值为 `"gui_000002_0042.png"`，`intent`、`CoT`、`actions` 等其余字段内容保持不变

#### Scenario: 引用文件一致性
- **WHEN** 转换完成
- **THEN** JSON 中引用的每个截图文件名都能在输出目录中找到对应文件，图片文件名、JSON 文件名、JSON 内引用三者使用同一新编号

#### Scenario: JSON 解析或改写失败
- **WHEN** 某数据集 JSON 读取失败或无法写入
- **THEN** 该数据集标记为失败、记录原因，继续处理其余数据集，最终状态为「部分失败」

### Requirement: 映射表输出

系统 SHALL 在目标目录生成一个 Excel 映射表，逐条记录源目录与重命名后的输出目录。

#### Scenario: 转换成功
- **WHEN** 全部数据集转换成功
- **THEN** 目标目录下生成 `数据集映射表_<时间戳>.xlsx`，包含列：序号、平台、采集人员、原文件夹编号、新编号、源目录、输出目录、状态、备注

#### Scenario: 部分失败或取消
- **WHEN** 部分数据集失败或用户取消
- **THEN** 映射表仍生成，已成功条目状态为「成功」，未处理条目状态为「未处理」，失败条目记录原因

### Requirement: 图形界面操作

系统 SHALL 提供 PyQt5 界面，包含交付 Excel 路径、数据母目录、目标目录三个选择项，「命中平台起始序号」表格，以及「开始转换」按钮、进度条、日志区和「取消」按钮。

#### Scenario: 默认路径
- **WHEN** 界面启动
- **THEN** 交付 Excel 默认预填 `datasubtool/长步骤交付.xlsx`（若存在）

#### Scenario: 起始序号表格
- **WHEN** 已选择 Excel 与母目录
- **THEN** 表格按 Excel 行序列出命中的平台，每个平台提供默认值为 1 的起始序号输入框，重新选择路径时保留已填写的值

#### Scenario: 参数校验
- **WHEN** 用户未选择 Excel 或目录即点击开始
- **THEN** 提示补全参数，不启动转换

#### Scenario: 执行中状态
- **WHEN** 转换进行中
- **THEN** 开始按钮禁用、显示当前数据集与整体进度（n/总数），用户可点击取消，界面保持响应

#### Scenario: 取消
- **WHEN** 用户点击取消
- **THEN** 当前数据集完成后停止后续复制，输出已完成部分的映射表，并在日志中说明已取消

#### Scenario: 预检失败展示
- **WHEN** 预检发现源目录缺失、重复条目、目标冲突或列缺失
- **THEN** 日志中逐条列出问题，不执行复制

### Requirement: 模块化与可测试性

系统 SHALL 将 Excel 解析、平台归一化、转换规划、复制重命名、JSON 改写、映射表写出实现为不依赖 Qt 的纯函数/类，界面仅负责交互与线程调度，并附带 pytest 单元测试。

#### Scenario: 单元测试覆盖
- **WHEN** 执行 `pytest datasubtool/tests`
- **THEN** 覆盖平台归一化、编号分配、冲突检测、文件重命名、JSON 引用改写、映射表列结构等用例且全部通过
