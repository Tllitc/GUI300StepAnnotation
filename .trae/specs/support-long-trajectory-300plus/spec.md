# 长轨迹（300+ 步）采集场景适配 Spec

## Why
当前工具以"单任务短轨迹"为预设：所有步骤截图的全屏 QPixmap 常驻内存、300+ 个编辑页同时挂在 QStackedWidget 中，标注数据只在任务结束或关窗时落盘，且仅支持首尾线性导航与末步撤销。当单任务轨迹达到 300+ 步时，会出现内存暴涨甚至崩溃、中途意外退出数据全损、无法快速定位和修正中间步骤、漏填项积累到收尾才暴露等问题，无法支撑长轨迹采集。

## What Changes
- **截图内存解耦**：步骤不再持有全屏 `original_pixmap`，预览图与侧栏缩略图按需从磁盘文件加载并缩放，内存占用与总步数脱钩。
- **增量自动保存**：每确认一步（防抖写入）/每结束一轮，将完整工作态写入 `gui_xxxxxx_draft.json`；崩溃或误关后零丢失。
- **断点续采**：任务初始化窗口新增"继续未完成任务"，选择含 draft 的 `gui_xxxxxx` 目录即可重建全部轮次与步骤继续标注。
- **长轨迹快速导航**：新增可折叠的步骤缩略图侧栏（步骤号 + 缩略图 + 动作类型 + 完成状态），支持点击跳转、输入序号跳转、快捷键上一步/下一步。
- **中间步骤编辑**：支持删除任意位置的步骤、在当前步之后插入漏采的截图；步骤号与坐标索引自动重编号。
- **必填校验与进度看板**：按动作类型校验必填项，侧栏标记缺失步骤；任务完成前输出缺失清单并可直接跳转；侧栏顶部展示总步数/完成数/动作分布/最近自动保存时间。
- **顺手修复**：`main.py` 中创建任务目录时平台参数硬编码为 `"mac"` 的问题。

最终产物 `gui_xxxxxx.json` 与 `gui_xxxxxx_coords.json` 的格式保持不变；新增的 draft 文件仅为工作态文件，已完成的旧任务目录不受影响。

## Impact
- Affected specs: 采集与标注主流程、数据持久化、任务初始化
- Affected code:
  - `annotation_editor.py`（主要改动：数据模型解耦、侧栏、校验、删除/插入、自动保存、恢复）
  - `data_manager.py`（draft 读写、续采目录扫描、截图按路径加载）
  - `main.py`（初始化窗口"继续未完成任务"入口、平台参数修复）
- 数据文件：新增 `gui_xxxxxx/gui_xxxxxx_draft.json`；任务正常完成后删除该 draft 文件。

## ADDED Requirements

### Requirement: 截图内存占用有界
系统 SHALL 不在内存中保留任何步骤的全屏原始 QPixmap；截图确认保存后，编辑器预览与导航缩略图均从 gui 目录下的截图文件按需加载并缩放显示。300+ 步任务运行时，图像相关内存不得随步数线性增长。

#### Scenario: 长轨迹采集内存平稳
- **WHEN** 用户连续采集 300 个步骤
- **THEN** 任何时刻内存中只存在当前步预览图与侧栏缩略图缓存，不保留 300 张全屏 QPixmap

#### Scenario: 重新截图不依赖内存原图
- **WHEN** 用户对历史步骤点击"重新截图"
- **THEN** 新截图直接覆盖写入原文件名，编辑器预览即时刷新，无需该步曾在内存中保留原图

### Requirement: 增量自动保存
系统 SHALL 在每次确认保存一个步骤后（约 1 秒防抖）、以及每次轮次切换/任务结束时，将当前完整工作态写入当前 gui 目录的 `gui_xxxxxx_draft.json`，内容包含：gui_number、当前任务指令、screen_info、app_type、已完成轮次 rounds、当前轮全部步骤（含截图文件名、动作数据、rect_info、selection_type）、坐标拉框 entries、最近更新时间。

#### Scenario: 采集过程中崩溃恢复
- **WHEN** 用户已采集 250 步但程序异常退出
- **THEN** gui 目录中存在 draft 文件，且其中包含截至最近一次确认的全部步骤数据

#### Scenario: 正常完成后清理 draft
- **WHEN** 用户通过"任务完成"正常结束并成功写出最终 JSON
- **THEN** draft 文件被删除，gui 目录只保留最终产物

### Requirement: 断点续采
系统 SHALL 在任务初始化窗口提供"继续未完成任务"入口；用户选择一个含 `gui_xxxxxx_draft.json` 的 gui 目录后，系统重建数据管理器、全部历史轮次与当前轮的所有步骤编辑器（含已填动作数据与磁盘截图预览），并定位到最后一个步骤，用户可直接继续截图采集。

#### Scenario: 打开未完成任务继续
- **WHEN** 用户选择一个含 draft 的 gui 目录
- **THEN** 标注编辑器恢复任务指令、轮次、全部步骤、截图预览、坐标数据，步骤指示器显示正确总数，新截图序号在已有文件之后递增

#### Scenario: 选择的目录无有效 draft
- **WHEN** 用户选择的 gui 目录不含 draft 文件或 draft 损坏
- **THEN** 系统提示无法恢复且不改变任何磁盘文件

### Requirement: 长轨迹快速导航
系统 SHALL 在标注编辑器左侧提供可折叠的步骤导航侧栏，每个步骤条目展示步骤序号、截图缩略图、动作类型与完成状态标记；点击条目即跳转到该步骤。系统 SHALL 同时提供"跳转到第 N 步"输入框与上一步/下一步键盘快捷键。

#### Scenario: 跨数百步快速定位
- **WHEN** 用户在第 300 步需要查看第 50 步
- **THEN** 可通过侧栏点击或输入序号 50 一次跳转到达，无需逐页点击"上一步"

#### Scenario: 侧栏状态随编辑实时更新
- **WHEN** 用户补全了某一步缺失的动作描述并确认
- **THEN** 侧栏对应条目的缺失标记消失，进度看板完成数同步更新

### Requirement: 中间步骤删除与插入
系统 SHALL 支持删除当前所在的任意步骤（含其截图文件与编辑器页），并支持在当前步之后插入一张新截图作为新步骤；操作完成后所有后续步骤的 `step` 编号与坐标 entries 的 step 索引 SHALL 自动重新计算为连续值。

#### Scenario: 删除中间步骤
- **WHEN** 用户在第 50 步执行删除并确认
- **THEN** 第 50 步截图文件被删除，原第 51 步变为第 50 步，后续步骤号连续，最终 JSON 与 coords 中的 step 索引无空洞、不错位

#### Scenario: 在中间位置插入漏采步骤
- **WHEN** 用户在第 50 步执行"在此步后插入截图"并完成拉框
- **THEN** 新步骤位于第 51 位，原第 51 步及之后步骤顺延，截图文件使用新的递增序号文件名

### Requirement: 必填项校验
系统 SHALL 按动作类型校验每个已确认步骤：非 terminate 类动作必须填写动作描述；坐标类动作（left_click/double_click/triple_click/right_click/middle_click/mouse_move/scroll/left_click_drag）必须具备非 (0,0) 坐标（全屏选择除外）；key 必须有按键；wait 必须有大于 0 的等待时间；type/open_app/open_url/answer 必须填写文本。缺失项在侧栏以可视标记提示。

#### Scenario: 结束任务前全量校验
- **WHEN** 用户选择"任务完成"但存在 3 个缺失必填项的步骤
- **THEN** 系统阻止结束并展示缺失清单（步骤号 + 缺失内容），点击清单项可直接跳转到对应步骤

#### Scenario: 单步缺失即时可见
- **WHEN** 某步骤动作描述为空
- **THEN** 侧栏该步骤条目显示缺失标记，进度看板的未完成数加 1

### Requirement: 进度看板
系统 SHALL 在侧栏顶部展示进度信息：当前任务指令、总步数、已完成/未完成步数、各动作类型数量分布、最近一次自动保存时间。

#### Scenario: 长任务进度可视
- **WHEN** 用户采集到第 300 步
- **THEN** 看板实时显示"总步数 300、已完成 N、未完成 M"及动作分布，无需翻页统计

## MODIFIED Requirements

### Requirement: 任务目录平台参数
创建任务目录时 SHALL 传入当前运行系统的真实平台标识（Windows 传 windows、macOS 传 mac），不再硬编码 `"mac"`；该参数当前仅作保留元数据，不影响目录结构。
